# 递归会话规程投影复核器

飞控规程在分发到各岗位前，协议工程师用它确认一份**递归会话规程**能被每个参与方**无歧义地投影为本地交互**——旁观方在分支后始终能判断下一条消息。

## 复核规则

- **录入上限**：最多 6 个参与方、12 个具名状态、48 条消息/选择分支；同一状态发出多条迁移即构成一个选择。
- **唯一发送方**：每个选择（同一状态的全部出边）必须拥有唯一发送方；指向同一接收方的分支标签不得重复。
- **消息守卫**：递归状态必须受消息守卫（状态图中每个环至少包含一条消息）。
- **可合并性**：非选择参与方（旁观方）仅当其各分支行为可合成为**同一发送方驱动且标签不重叠的外部选择**时才能继续，否则拒绝并定位**首个不可投影点**（状态 + 两条不可合并的分支路径）。
- **协归比较**：递归局部类型以协归（互模拟）方式比较，名称不同但行为相同的环不视为冲突。

复核通过时展示每个参与方的**规范本地状态机**（状态表 + μ 表达式）。

## 内置演练

- **演练一（应通过）**：A 选择后，两支均由 B 向 C 发送不同标签（l1/l2）——C 可合并为同一发送方驱动、标签不重叠的外部选择。
- **演练二（应拒绝）**：A 选择后，C 在一支等待 B、另一支等待 D——外部选择发送方不一致，拒绝并展示两条不可合并路径。

## Docker Compose（推荐）

```bash
# 对外端口可配置（默认 8080），健康地址为 http://localhost:${APP_PORT}/health
APP_PORT=8080 docker compose up --exit-code-from verify
```

- `app`：React + TypeScript 页面与后端服务（`GET /health`、`GET /api/drills`、`POST /api/verify`）。
- `verify`：依次执行**投影规则测试**、**前端构建**、对**健康地址与演练结果的 HTTP 冒烟**，完成后以退出码结束（0 = 全部通过）。

## 本地开发

```bash
npm install
npm test                 # 投影规则测试
npm run build            # 后端（tsc）+ 前端（vite）构建
npm start                # http://localhost:8080（PORT 可覆盖）
APP_URL=http://localhost:8080 npm run smoke   # HTTP 冒烟
```

前端开发热更新：`npm run dev`（Vite，代理 `/api` 到 8080）。

## 目录结构

```
shared/    投影引擎：模型与校验（model.ts）、投影/合并/协归比较（engine.ts）、内置演练（drills.ts）
server/    HTTP 服务（node:http，无外部依赖）
web/       React + TypeScript 页面（Vite 构建到 web-dist/）
tests/     投影规则测试（node:test）
verify/    HTTP 冒烟脚本（健康地址 + 演练结果）
```
